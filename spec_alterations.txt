Spec Alterations
================

1. Graph Connectivity (implemented)
-----------------------------------
Problem: Walk graph has disconnected components causing zero-score anomalies.
Solution: Filter graph to largest connected component before snapping POIs and grid points.

2. Kernel Decay Rate (implemented)
----------------------------------
Problem: Exponential kernel with lambda=300m decays too slowly, causing high scores
to "bleed" into areas like the Charles River where walking access is limited.

Original spec: lambda=300m
Selected: lambda=120m (after comparing 100-200 range)

Decay at λ=120m:
- 50m:  66% weight
- 100m: 43% weight
- 200m: 19% weight
- 500m: 1.5% weight

This creates sharp contrast between POI-dense and sparse areas while maintaining
smooth gradients in transition zones.

3. Comparison Viewer (implemented)
----------------------------------
Addition: Side-by-side comparison viewer for evaluating different kernel parameters.

New CLI: compare.py
  python compare.py \
    --pbf file.pbf \
    --bbox "min_lon,min_lat,max_lon,max_lat" \
    --configs "name1:exponential:150" "name2:power_law:2:50" \
    --out output_compare

Features:
- 2-3 maps side by side with synchronized zoom/pan
- Shared color scale across all panels for fair comparison
- Panel headers showing kernel parameters
- Click any cell to see scores across all configs

4. Visualization: Fill Layer (implemented)
------------------------------------------
Problem: MapLibre heatmap layer changes appearance with zoom level.
Solution: Use polygon grid cells with fill layer instead of point heatmap.
Each grid cell is a square polygon that maintains consistent color at all zoom levels.

5. Power Law Kernel Formula (implemented)
-----------------------------------------
Problem: Original formula K(d) = 1/(d+d0)^p gave tiny values (~0.0001).
Solution: Normalized formula K(d) = 1/(1 + d/d0)^p

This gives:
- K(0) = 1.0 (same as exponential)
- Comparable decay rates when d0 matches lambda
- Power law tail behavior for p > 1

6. Grid Snapping Optimization (implemented)
-------------------------------------------
Problem: Grid point snapping to graph nodes used O(V) linear search per grid point,
resulting in O(V * n_grid) = O(n²) complexity. For large grids (17,750 points) with
large graphs (300k nodes), this was 5.3 billion comparisons.

Solution: Use scipy.spatial.cKDTree for O(n log n) snapping.

Measured speedup: 14x faster (106.9s → 7.7s on medium test)
